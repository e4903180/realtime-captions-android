# Where caption delay comes from

Generated by `:desktop --latency-breakdown` on 2026-11-27 (20 logical CPUs). Clean Taiwan-accent speech: zh-TW TTS dialogs and 16 Common Voice zh-TW sessions, turn times trimmed to the voice. First text = from the moment a person starts speaking until the first character is on screen; line done = from when they stop until the line is final.

| Setting | First text p50 / p90 (s) | Line done p50 / p90 (s) | CER | RTF |
|---|---|---|---|---|
| X-ASR 160 ms, 100 ms audio chunks (app today) | 0.95 / 1.29 | 0.65 / 0.85 | 10% | 0.14 |
| same, compute counted as zero | 0.94 / 1.27 | 0.57 / 0.75 | 10% | 0.13 |
| same, 20 ms audio chunks | 0.91 / 1.26 | 0.60 / 0.80 | 10% | 0.13 |
| X-ASR 480 ms model, 100 ms chunks | 1.13 / 1.55 | 0.68 / 1.03 | 9% | 0.06 |
| line end after 0.3 s silence (now 0.4) | 0.95 / 1.29 | 0.51 / 0.69 | 10% | 0.13 |
| 4 CPU threads (now 2) | 0.95 / 1.28 | 0.64 / 0.83 | 10% | 0.12 |
| combined: 20 ms chunks + 4 threads (**app default now**) | 0.91 / 1.26 | 0.59 / 0.80 | 10% | 0.12 |
| combined: 20 ms chunks + 4 threads + line end 0.3 s | 0.92 / 1.30 | 0.49 / 0.65 | 11% | 0.12 |

Rows with 20 ms chunks were re-measured after fixing a bug: with chunks shorter than one 512-sample
VAD window, the VAD reported "no speech" for chunks that did not complete a window, which ended
lines early. The fixed VAD keeps its last decision until a window is complete.

## What this means

- **First text (~0.9 s) is mostly the model and the speech itself.** Compute on this PC is about
  0.01 s of it and the 100 ms audio chunking about 0.04 s. Going clearly faster needs a model with
  less look-ahead; X-ASR 160 ms is already the fastest Chinese streaming model we tested
  (480 ms adds ~0.18 s).
- **Line done (~0.6 s) is mostly the wait to be sure the speaker stopped** (0.4 s of silence plus
  0.2 s of unchanged text). Compute and tail padding add ~0.08 s.
- Phones are 3–5× slower than this PC, so compute and chunk size matter more there.

## Chosen for the app

20 ms audio chunks and 4 recognizer threads: first text −0.04 s, line done −0.05 s, same accuracy.
Line end stays at 0.4 s silence: 0.3 s finishes lines another 0.1 s sooner but raised CER from
10% to 11% here and splits sentences more often in noise (benchmark.md).
