# 2026-11-28 說話者字母穩定（ADR-036）

## 問題

模擬器驗證（Pixel 8，debug wav：家庭晚餐 3 人，正確 A B C A B C）：

- 畫面最後是 A B A A B A。第 3 句說完時 logcat 記成 `final [C]`，約 6 秒後畫面上變成 A。
- 不清除再按開始，上一輪的舊句子會 A→C→A 來回變。

## 找原因

1. 程式審視：每句結束都用門檻 0.45 重新分組（ADR-027），比即時分群寬鬆，C 在 A 的第二句加入後被併進 A。併錯的群心交回即時分群後，C 從此消失。
2. 重新分組不分輪次；字母投票用的是已經被改過的標籤，而且照群大小貪婪分配，所以會互換字母。
3. desktop 的 `--speaker-recluster` 只在檔案最後重新分組一次，和 App 的「每句重新分組再交回」不同，所以之前的評測看不到這個問題。新增「App regroup」模式，並記錄已顯示句子的字母變更次數。

## 修正

見 ADR-036：門檻 0.60、只重新分組這一輪、舊句子只能整個字母一起改、字母依第一次顯示的標籤分配、短句不沿用上一個人、音量背景過濾預設關、交回群心不會遺漏。

## 驗證

- 核心單元測試新增 `SpeakerStabilityTest`（7 項），全部通過；`:app:testDebugUnitTest`、`:desktop:test` 通過。
- TTS 對話（App 模式）：中文說話者正確率 87.2% → 93.2%，字母變更 0.4 → 0 次／段（docs/benchmark-speakers.md）。
- 模擬器 Pixel 8：A B C A B C，字母 0 次變更；不清除再跑一次，舊句子不動。

## 順便修的

- 看電視模式不能往回滑（PR #34）：辨識中每秒好幾次的新字把清單拉回最底、取消使用者的拖曳。改成手指一碰到清單就停止跟隨，加「↓ 回到最新」。

## 還沒做

- iPhone 的 `reclusterThreshold` 還是 0.45（這個 PR 不動 ios/）。
- 真實手機上的長時間對話還沒測。
