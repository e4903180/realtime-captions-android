# 2026-11-28 檢視與整理：benchmark 對齊 App、計分、CI、文件

## benchmark 量的是 App 出貨的設定

讀程式確認 Android App（`SherpaOnnxEngine.kt`、`CaptionViewModel.kt`）用：停頓 0.6 秒結束一行、`CaptionAssembler` 1.5 秒內同一人接行、每 20 毫秒送聲音、4 核心。`:desktop` 的預設卻是 0.4 秒、不接行、100 毫秒、2 核心，所以報告的數字不是使用者看到的。

- `:desktop` 預設改成 App 的設定（`BenchDefaults`）。`--legacy-config` 改回舊設定，方便跟舊報告比；`--vad-end`、`--merge-gap`、`--chunk-ms`、`--threads` 可個別調。原本的參數都照舊可用。
- 每份報告開頭多一行 **Config.**，寫出所有會影響結果的設定，並註明跟 App 一不一樣。
- 接行在 benchmark 裡用模擬的時鐘算，跟 App 畫面一樣；每句仍單獨記錄（延遲、說話者正確率照句算），重新分組照「這句在哪一行」對回去。
- 順手修了兩個計分問題：
  - 字幕組裝最多留 200 行，10 分鐘的會議超過時前面的字被丟掉，錯字率被高估。benchmark 現在保留全部行。
  - 空白的定稿結果原本被記成「上一行的文字」，會重複計算說話者、也多算假字幕行數。現在不算。
- 只用兩段合成對話快速確認能跑：App 設定錯字率不變（1.1%），定稿 p50 0.82 → 1.08 秒（停頓 0.4 → 0.6 秒的代價）。完整報告沒有重跑，數字之後用新預設重產。

## 計分

- `Metrics.kt` 加數字正規化（`NumberForm`）：中文數字轉阿拉伯數字（一百二十三 → 123、兩千三 → 2300、二〇二六 → 2026），每個數字一個 token；或反過來把阿拉伯數字逐字轉中文。報告的錯字率列原始值和「CER (numbers)」兩欄。加了單元測試。
- `tools/whisper-bench/bench.py` 的台灣字形表跟 `Metrics.kt` 對齊（多了 爲→為、綫→線、衆→眾），並有測試檢查兩邊一致。
- Python 的 Whisper／Google／Azure 對照測試之後會把完整辨識文字存進結果 JSON（原本只留前 300 字），以後改計分不用重跑。舊結果沒有重跑。

## CI

- 快取 `~/.cache/realtime-captions`（`DownloadFile` 下載 sherpa-onnx 的位置），key 用 buildSrc 原始碼的 hash，版本或 SHA-256 一改就重新下載。
- `DownloadFile` 加連線 30 秒、讀取 60 秒逾時，卡住時會失敗重試，不會一直掛著。
- 工作加 `timeout-minutes`，同一個分支新的推送會取消還在跑的舊工作（`concurrency`）。
- 加 `./gradlew :app:lintDebug`，只出報告不擋合併（`abortOnError = false`），報告上傳成 `lint-report`。本機跑約 6 分鐘，目前 1 個錯誤（`AudioInput.kt` 建 `AudioRecord` 前沒檢查麥克風權限，MissingPermission）、8 個警告；Android 畫面程式由別人在改，這次沒修。
